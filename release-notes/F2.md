# F2: MCP new output shape and path input

Behaviour changes (CHANGELOG `## 0.8.0`):
- MCP `clean_text` / `clean_json` return `{warnings, summary, text|value, signals}` in that order; `detail="full"` adds value-free `findings` (flat: `entity_type, score, start, end, action, reason`, plus `path` for JSON). `stat_text`, `language`, `policy` and the nested `findings[].entity` / `findings[].finding` shape are gone.
- Both tools declare `outputSchema` and tool annotations (read-only, non-destructive, idempotent, closed-world, title).
- Errors are `fastmcp.exceptions.ToolError` with a remedy (PII-mode mismatch was `ValueError`).
- New `clean_text(path=...)`, off unless `SCT_MCP_ROOT` is set; `SCT_MCP_MAX_BYTES` (default 1 MiB). `create_mcp_server(cleaner=None, *, root=None, max_bytes=None)`.

README: link `docs/MCP.md` from the MCP section; llms.txt: mention `SCT_MCP_ROOT`.

Integrator notes:
- Built before K1 landed: `sct/mcp_server.py` uses `sct.signals.public_view` / `merge_views` when importable and otherwise a local fallback (`_fallback_view`, `_fallback_merge`) built from today's metadata. Once K1 is merged, delete the fallback and the `_signals(result, chars)` / `_merge` wrappers can call K1 directly (`chars` arg unused then).
- `tests/test_mcp_server.py::SIGNAL_KEYS` mirrors `PUBLIC_VIEW_KEYS`; switch it to import `sct.signals.PUBLIC_VIEW_KEYS` after K1.
- CI does not install the `mcp` extra; the FastMCP-only tests skip there, the rest run against a stand-in `ToolError`.
