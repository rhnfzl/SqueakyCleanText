## Section 2: Function-Level Drill-Down in Node Tooltips

### What
Expand the existing node click tooltip to include a collapsible **"Methods"** section listing all public and key private methods.

### Format
```
▼ Methods (N)
  method_name()   :line  One-sentence role description
```

### Data per key node

**TextCleaner (sct/sct.py)**:
- `__init__()` :17 — Build pipeline from frozen config, init language detector and NER
- `_init_pipeline()` :91 — Populate pre-fuzzy and post-fuzzy step lists from config flags
- `_detect_language()` :134 — Lingua-based language detection, honours `cfg.language` pin
- `_process_single()` :149 — Two-phase pipeline + fuzzy + NER + statistical model
- `process_batch()` :198 — ThreadPoolExecutor for parallel per-text processing
- `aprocess_batch()` :239 — Async wrapper via `run_in_executor` for FastAPI/aiohttp
- `warmup()` :247 — Pre-load NER models for all supported languages
- `process()` :263 — Single-text convenience wrapper → `process_batch([text])[0]`

**TextCleanerConfig (sct/config.py)**:
- `__post_init__()` :162 — Validates, normalises, and computes `supported_languages`

**GeneralNER (sct/utils/ner.py)**:
- `__init__()` :87 — Lazy model registry, per-model locks, backend routing
- `_get_lock()` :140 — Double-checked per-language Lock creation
- `_ensure_loaded()` :170 — Lazy model load with `_load_lock` double-check
- `_get_pipeline()` :203 — Load-on-demand model retrieval
- `ner_process()` :315 — Main NER entry: chunk → infer → ensemble → Presidio anonymise
- `_simple_chunk()` :274 — Token-aware chunking for GLiNER (max_tokens * 4 chars)
- `split_text()` :412 — Hierarchical token-aware splitting via CHUNK_DELIMITERS
- `__del__()` :485 — ONNX session + Torch pipeline cleanup on GC

**ONNXNERPipeline (sct/utils/onnx_pipeline.py)**:
- `__call__()` :106 — Tokenise → ONNX inference → aggregate to entity spans
- `_aggregate_simple()` :162 — HF `aggregation_strategy="simple"` reimplemented in NumPy
- `load_onnx_ner_model()` :251 — Download from Hub, optional INT8 quantization, create session

**Constants (sct/utils/constants.py)**:
- `build_month_names_dict()` — Merge custom month names into MONTH_NAMES_MULTILINGUAL
- `build_date_regex()` — Compile DATE_REGEX from month name dict
- `build_fuzzy_vocabulary()` — Build fuzzy vocab and per-language vocab dicts

### Interaction
- Section is collapsed by default, toggled with a click on "▼ Methods (N)"
- Clicking a method row copies `file:line_number` to clipboard and shows a toast "Copied sct/sct.py:149"

## Section 3: Call Graph in Pipeline Sim Sidebar

### What
A new **"Call Graph"** section in Pipeline Sim left sidebar (below Pipeline Stats), showing the actual method call hierarchy.

### Structure
```
TextCleaner.process("text")
  └─ process_batch([text])
       └─ ThreadPoolExecutor
            └─ _process_single(text)
                 ├─ _detect_language()          → language
                 ├─ PHASE 1 (pre-fuzzy pipeline)     [7 steps]
                 │    fix_unicode → emoji → HTML → URLs → emails → dates
                 ├─ fuzzy_replace_dates(text, lang)  ← explicit call
                 ├─ PHASE 2 (post-fuzzy pipeline)    [≥7 + custom]
                 │    years → phones → numbers → currency → letters → symbols → whitespace
                 │    └─ [custom_pipeline_steps] (user-defined)
                 ├─ ner_process(text, language)
                 └─ _statistical_model_processing(text, language)
                      ├─ smart_casefold / casefold
                      ├─ remove_stopwords
                      └─ remove_punctuation
```

### Interaction
- Rendered as nested `<ul>` with CSS tree lines
- Clicking a leaf node (e.g., "Replace URLs") scrolls Pipeline Sim output to step 5 and highlights it with a 2s pulse
- Phase labels ("PHASE 1", "PHASE 2") use distinct background colors matching the existing pipeline step color scheme
- When a step is toggled off in Pipeline Config, its node in the call graph dims to 40% opacity
- "ThreadPoolExecutor" node shows "(parallel for batches)" tooltip
