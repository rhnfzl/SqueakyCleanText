Caller migration

Active callers in this repository use the current interfaces. No compatibility layer was added.

  • Cleaners receive TextCleanerConfig; model choices use ner_models.
  • Document concurrency uses max_workers. The release benchmark function, CLI, tests and documentation now use that name.
  • The release benchmark command uses --max-workers; its report settings use max_workers, and filenames use -W.
  • NER finalization receives synthetic_caches. Callers import chunking and placeholder rules from their owning modules.
  • The pinned SCT 0.8.2 adapter passes workers positionally, which both the pinned and current signatures support.

Model input batches and dataset batches keep their own batch_size parameters. Archived results retain the original schema and filenames.

Other repositories and installed third-party applications are outside this migration audit.

Decisions and evidence

These problem references describe baseline commit 2dab9c7, before the implemented changes. The audit covered 115 Python source modules and their callers, tests, configuration and exports.

1. Define masking order once

Keep cleaning methods and boundary substitutions in one cleaner-owned plan.

  • sct/sct.py:354-387 and sct/streaming.py:74-89 independently define order, switches and patterns.
  • tests/test_streaming.py:151-175 repeats both implementations and requires coordinated edits. Remove this mirror test; keep split-safety regressions.

2. Pass synthetic state with each document

Replace the caller callback with explicit per-document caches owned by NER finalization.

  • sct/sct.py:673-689 restores thread-local state through before_finalize in sct/utils/ner.py:665-721.
  • Keep regex and model replacements consistent within a document and isolated across documents.

3. Share placeholder syntax through a stable module

  • ner.py:62, special.py:19 and score.py:33-34 repeat marker grammar.
  • sct.py:271-272,525-526,1144 imports that grammar through the model orchestrator.

4. Keep model identities beside revisions

  • sct/config.py:48-98 maintains four parallel maps and copies multilingual checkpoints.
  • Derive model and revision maps from paired facts. Preserve default routing and pinned revisions.

5. Put window geometry beside chunk splitting

  • sct/utils/ner.py:767-843 holds pure window planning, apart from ner_chunking.py.
  • Move geometry and window records; keep tokenizer selection and overlap validation with model orchestration.

6. Remove obsolete configuration paths

  • sct/config.py:893-938 mirrors every field into mutable globals and reconciles naming exceptions.
  • ner_models_list and _reconcile_ner_models maintain tuple and mapping representations.
  • Use explicit immutable configs and one model mapping. Keep five default routes, four supported languages and custom-map default filling.

7. Remove deprecated aliases and empty model placeholders

  • sct/sct.py:106-146 exposes renamed private processors through warning-only properties.
  • process_batch and aprocess_batch resolve obsolete batch_size into max_workers.
  • OTTER_NER_MODELS and MMBERT_NER_MODELS are empty speculative maps. Remove them and their existence-only test.

8. Keep frozen benchmark facts together

  • benchmarks/compare/entries.py and isolated adapters copy prompts, labels and revisions.
  • Use one standard-library metadata module. Include imported helper sources in cache fingerprints so changed facts cannot reuse stale predictions.

9. Separate benchmark execution from scoring

  • compare/speed.py:35 imports eleven helpers from the quality runner.
  • tune.py and report.py call private JSON and mean functions from other workflows.
  • Move shared execution into a runtime module and expose the internal functions callers actually need.

10. Share test loading and remove unused registry leftovers

  • Three benchmark test modules duplicate adapter loading or import another test module.
  • entries.RESERVE has no callers; tuning imports unused spaCy constants through lint suppressions.
  • Remove stale comments about copied labels and unpublished models. Keep external constraints and useful regression tests.

Consequences

Repository callers are migrated to TextCleanerConfig, ner_models and max_workers. Utility classes remain available from their own modules.

Current output formats, tuple results, optional backends and supported integrations remain. No new dependencies, word lists or model rules are added.

Comment cleanup is complete within the audited scope. Tests tied only to retired interfaces or copied implementation details were removed; behavior and safety checks remain.

Required special cases

  • Streaming retry state and closed failure behavior retain buffered text after errors.
  • Custom-pattern timeouts, source markers and protected values prevent leaks and replacement collisions.
  • Privacy-policy overlap precedence differs from ordinary span merging and stays separate.
  • Model fallbacks, optional adapters, process rebuilding and revision pinning protect real runtime differences.
  • Benchmark retries, GPU package repair, licensed prediction deletion and hardware anonymization remain required.
  • Pinned SCT 0.8.2 benchmark calls retain its historical worker argument. This is an active reproducibility requirement.
  • ProcessResult tuple behavior and configurable legacy_type_names remain active user contracts.
