Work order

  1. Baseline: freeze current behavior and qualify optional dependencies (P0).
  2. Core: define findings and coordinates, expose detectors, apply policy once, then forward field context (C1-C5).
  3. Corpus and storage: implement selection, restartable jobs and encrypted token storage (D1-D3, S1-S2).
  4. Integrations and decisions: add document extraction, credential scanning, language abstention and routing evaluation (E1-E2, L1-L3).
  5. Combined acceptance: validate interactions and prepare reviewed release changes (R1).

Corpus and storage can proceed independently after P0. Shared configuration and dependency files need serial integration.

Acceptance gates

  • Compatibility: current outputs, public imports, tuple results, batch order and replacement modes pass frozen checks.
  • Privacy: default findings, errors, logs and manifests contain no raw sensitive values.
  • Coordinates: Unicode and normalization tests distinguish exact, covering and unavailable source positions.
  • Recovery: interrupted jobs replay safely; changed input or settings reject stale state.
  • Integrations: real optional-provider smoke tests pass in project environments on supported Python versions.
  • Routing: compare a fixed baseline on frozen data and hardware. Require fewer expensive calls, lower median latency and the declared no-added-exposure test before promotion.

If routing fails its promotion gate, deliver the experimental implementation and the measured result. Keep always-run routing as the baseline.

Decisions that prevent misleading guarantees

Codex proposes these limits. Exact source mapping remains uncertain for custom transforms.

  • Arbitrary custom string transforms cannot always preserve exact original offsets. Mark unavailable mappings or reject them in strict mode.
  • PII-normalized deduplication can collapse different records. Default to reporting; require an explicit basis before removing output records.
  • Encrypted SQLite is a reference integration. Applications still own authorization, keys, backup retention and access control.
  • Expiry and logical deletion do not erase storage media, old backups or database journal files.
  • Document extraction protects cleaned text and structural output. It does not redact the original PDF or image.
  • Existing browser and bounded-streaming restrictions remain explicit. These features do not imply parity across every surface.

Release and rollback

Merge opt-in milestones through reviewed PRs. Keep a legacy configuration for rollback. Publication and any default migration need a separate release decision.
